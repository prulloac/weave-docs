# Contract Layer

## Purpose

The contract defines the language-neutral wire model shared by the Go engine, CLI, MCP server and
extensions. It is the single source of truth for documents, keywords, graph nodes and search
results.

The previous v1 is overridden in place by [ADR 0001](../adr/0001-keyword-fuzzy-search-and-ui-retirement.md).

## Package Layout

```text
contract/v1/
├── schema/
│   ├── defs.schema.json          # authoritative definitions
│   ├── bundle.schema.json
│   ├── concept.schema.json
│   ├── graph.schema.json
│   ├── search.schema.json
│   ├── list-results.schema.json
│   ├── navigation.schema.json
│   ├── show.schema.json
│   ├── backlinks.schema.json
│   ├── path.schema.json
│   ├── error.schema.json
│   ├── envelope.schema.json
│   └── cli.schema.json
├── types.go                      # hand-written Go structs, schema-tested
└── golden/
    ├── manifest.json             # cases and operations to export
    ├── bundles/                  # input OKF fixtures with keywords
    └── expected/                 # generated expected JSON
```

JSON Schema is authoritative. Go structs are hand-written and validated against the schemas.
The golden corpus is regenerated by `go run ./cmd/contract-export` and reviewed as a diff.

## Document Model

### Concept

```json
{
  "id": "concepts/oauth-token-rotation",
  "path": "concepts/oauth-token-rotation.md",
  "type": "Concept",
  "keywords": ["oauth", "tokens", "rotation"],
  "title": "OAuth Token Rotation",
  "description": "How tokens rotate.",
  "status": "stable",
  "frontmatter": {"type": "Concept", "keywords": ["oauth"]},
  "body": "\n# OAuth Token Rotation\n...",
  "privacy": {"policy": "encrypt", "key_id": "docs"},
  "content_kind": "text",
  "media_type": "text/markdown",
  "content_metadata": {},
  "links": []
}
```

Required: `id`, `path`, `frontmatter`, `type`, `keywords`, `body`, `links`.

Rules:

- Concept id = bundle-relative path minus `.md`.
- `keywords` must be a non-empty list of non-empty strings.
- Missing/invalid keywords set `has_keywords: false`; the document is invalid for the Weave
  profile but remains in the bundle, graph and fuzzy index.
- Unknown frontmatter keys are preserved.
- `privacy`, `content_kind`, `media_type` and `content_metadata` are optional additive fields for
  encrypted documents and blob assets; see [Privacy Directives](../../specs/privacy-directives.md)
  and [Generic Blob Assets](../../specs/blob-assets.md).
- `body_codec`, `size` and `stored_size` are storage-only fields and are not part of the CLI contract.
- Links keep `raw`, `target`, optional `resolved` and `resolves_in_bundle`.

### Validation

```json
{
  "valid": false,
  "concepts": [
    {
      "id": "concepts/example",
      "has_frontmatter": true,
      "has_type": true,
      "has_keywords": false,
      "warnings": ["missing keywords"]
    }
  ],
  "warnings": []
}
```

Bundle `valid` requires frontmatter, type and keywords for every concept.

### Graph

Nodes carry `keywords` plus type, title, status, tags and in/out degree. Edges are `link`, `related`
or an extension-provided kind such as `contains`, `depends_on`, `parent_of`, `imports` or `declares`,
with optional raw link text. `dangling` maps source ids to unresolved links.

## Search Model

```json
{
  "query": "oauth tokn",
  "mode": "hybrid",
  "top_k": 10,
  "keyword": [],
  "fuzzy": [],
  "hybrid": [],
  "lexical": [],
  "semantic": []
}
```

- `mode` is `keyword`, `fuzzy`, `hybrid`, `bm25` or `semantic`.
- `top_k` is 1..100, default 10.
- `keyword` contains `KeywordHit` entries with matched keywords and score.
- `fuzzy` contains `FuzzyHit` entries with matched fields and optional snippet.
- `hybrid` contains `HybridHit` entries with keyword/fuzzy or BM25/fuzzy scores plus the total.
- `lexical` is additive for `bm25` and persistent `hybrid`; it carries raw and normalized BM25 scores.
- `semantic` is additive for `semantic` mode and carries cosine scores.
- A reranker adds `rerank_score` to the selected hit list and blends `0.5 * core + 0.5 * rerank`.
- A scorer adds `scorer_score` and a `scorer` block with name, weight and candidate count.
- Every list is independently capped at `top_k`.
- Scores and ordering are deterministic.
- `find` and `FindResult` no longer exist.

## CLI Envelope

```json
{
  "contract": "weave.contract/v1",
  "cli": "weave.cli/v1",
  "ok": true,
  "result": {}
}
```

Failure envelopes contain `error.code`, `error.message` and optional `error.details`.
The operation catalogue contains `search`, not `find`.

## Parsing Semantics

| Rule | Contract behavior |
| --- | --- |
| Required fields | `type` and `keywords` |
| Missing keywords | Invalid concept; excluded from keyword search; kept for fuzzy/graph |
| Reserved names | `index.md`, `log.md` anywhere |
| Root index | Only the bundle-root index sets version/index |
| YAML | Full YAML via `yaml.v3`; unknown keys preserved |
| Links | Source-preserving; anchors/queries stripped for resolution |
| Symlinks | Files followed; directories one level with cycle guard |
| Invalid UTF-8 | Per-file parse error, skipped |
| Empty bundle | Valid, warning emitted |
| Determinism | Sorted concepts, graph nodes/edges, search results |

## Golden Corpus

- `manifest.json` declares cases, search queries/modes/top-K and navigation operations.
- `go run ./cmd/contract-export` writes `golden/expected`.
- `go test ./contract/v1` validates every golden against the schemas and round-trips through Go
  structs.
- Golden updates require review; CI fails on drift.

## Versioning

- `weave.contract/v1` is the shipped contract.
- `weave.cli/v1` remains the envelope version.
- Until 1.0.0, `contract/v1` may evolve in place. After 1.0.0, breaking changes require
  `contract/v2`; additive fields and enum values remain allowed. No compatibility mode for the old
  v1 is provided.
